# P7 Gate 2B Gold 分级审核准入协议提案

日期：2026-10-25。状态：**draft / awaiting_explicit_user_approval / effective=false**。

本文件只供审批，不替换 [现有 Gate 2B 要求](p7-gate2b.md)，也不改变当前 blocked 状态。原 60 条人工审核 pending、首次技术审核及 [用户提供的第二轮技术复核](p7-gold-second-review.md) 均按原事实保留。批准本协议不等于批准具体 Gold、执行 Registry 确认、实施兼容修订或授权付费 Live；这些行为需要各自明确的决定和证据。

## 1. 评估结论与现有证据

建议采用“全量技术审核 + 全量适用的确定性检查 + 风险覆盖/随机抽样人工复核 + 例外逐项裁决”。可以减少同一业务定义在不同题目中的重复签署，但必须公开降低了全量人工复核覆盖率。该方案是实验准入治理调整，不提高 Gold 的数学正确性，也不承诺正式 Agent 的成功率。

现有证据：

- 首次技术审核为 50 consistent、9 needs_resolution、1 mismatch；一致的 50 条包含 SQL-only 19、RAG-only 15、SQL+RAG 16。
- 全包 27 个预期数值目标已由独立于运行配方的离线代码复算，原 15 条 PG/MCP 参考查询证明保留；10 个不可计算指标目标已有理由审查。这些是目标数，不能当成已审核的独立业务任务数。
- 40 条文档任务已有原文/身份/跨度核验；真实检索质量尚未评测。原文存在/hash 正确，不证明语义足够、时期适用或因果成立。
- 13 个 Dataset 快照涉及 14 个 Semantic 提案、22 个 Metric 提案。它们仍有需要真实人工确认的覆盖范围、单位、合同身份/历史完整性等声明。负例中故意缺失的单位或授权不能因审核协议获批而被补齐。
- 同一 AI 工作链参与了 Gold 构造与技术审查；另一份实现和第二轮技术意见增加了证据，但不能宣称独立人员盲审已完成。

## 2. 新旧协议差异

| 项目 | 原要求 | 拟议新要求 |
|---|---|---|
| 人工逐题审核 | 60 条均需独立人工签署 | 50 条一致项抽查至少 20 条；剩余 10 条逐项人工裁决；异常触发扩查 |
| AI 技术审核 | 人工审核支持材料 | 全量独立证据通道，可满足结构、引用定位和显式一致性审查；不能替代业务授权或最终人工裁决 |
| 确定性验证 | 参考证明/复算支持 | 全量适用项必须有精确输入、版本、代码及结果 hash；非适用项标 not_applicable，不伪记 passed |
| 共用口径确认 | 容易在每题重复签署 | 人工审阅版本化定义清单后可一次批量明确确认；每题引用相同精确定义，不能用通用签名覆盖未列版本 |
| 未抽中题目 | 仍待人工逐题签署 | 历史 pending 不变；新准入字段可记 eligible_by_protocol，不记 human_approved |
| 人工身份 | 独立审核人及逐项证据 | 接受真实人工及可追溯批量决定；若由项目负责人审核，明确该身份与独立性，不冒称外部第三方盲审 |
| 历史与原 seal | 不覆盖 | 完全保留；修订须有 parent seal、逐项差异和新版本身份 |
| 生效 | 现有要求有效 | 用户明确批准本文件的精确版本后才生效，不追溯宣布旧要求已完成 |
| Live 准入 | 审核及全部工程准入后另行授权 | 相同；不能只因抽样完成就忽略 Runner/Scorer、权限或恢复阻断 |

## 3. 证据字段分离（仅设计）

不修改封存包或数据库；未来在独立、追加的审核 sidecar 中表达：

| 字段 | 含义与允许状态 |
|---|---|
| legacy_human_review_ref | 指向原 pending 记录及其 hash；原文件不覆盖。现有 review_decision 等字段按原 Schema 保留，不伪造已有 human_review_status 字段。 |
| ai_technical_review | consistent / needs_resolution / mismatch；附模型/操作者类型、审查工件 hash、检查范围及已知限制。 |
| deterministic_validation | passed / failed / not_applicable / not_run；分别记录数值、单位、窗口、版本和原文引用检查及其代码/输入/结果 hash，不能仅用一个总布尔值。 |
| human_review_events | 未抽中为 not_sampled，抽中未审为 pending；实际决定可为 approved / needs_revision / rejected。审核人、实际时间、Case/定义清单、证据引用及独立性如实记录；没有实际确认时均不自动填写。 |
| tiered_admission | not_evaluated / eligible_by_protocol / blocked / superseded_for_future_use；必须绑定 protocol hash、pack/Gold/pins hash、抽样清单及人类批准记录。 |

eligible_by_protocol 表示满足已批准的分级准入规则，不表示每题由人审批，也不是 P3 verified 或模型业务完成。实际人工决定可一次签署包含多个 Case 的精确清单，但不能凭一句不限定范围的“看过了”自动批准所有题。

## 4. 50 条一致项的抽样标准

基线为 **20/50**：SQL-only 8/19、RAG-only 6/15、SQL+RAG 6/16。每层至少 2 条按冻结算法随机抽取，剩余名额按预先写明的风险覆盖表选取；风险样本不能根据预计容易通过程度选。任何无法在基线中覆盖的必需风险须增加样本，不能挤占每层的随机名额。

必需覆盖：

1. 分/元金额、精度、paid/币种过滤、右开边界、完整空窗口及源版本。
2. 合同/客户流失差异、重订阅/并行合同、时点活跃、事件 feature 与单位。
3. MRR 不支持、零分母、未确认单位/历史、重复粒度、未知版本、未授权请求等拒答/阻断类别。
4. RAG 多来源、新旧文档、时间适用性、无关材料及注入；各关键独立 Source 组和定义模板不能只由大量同源题替代。
5. 混合任务的指标与文档分离、partial、因果未验证；同一案例可覆盖多项风险，但不能重复计入样本数量。

拟采用以下可复现抽样步骤，**本轮不实际抽样**：

- 协议批准后，先冻结 50 个 Case 及风险标签、必选覆盖表、抽样实现和候选代码 hash。固定风险样本后，从各层剩余项中抽随机样本，无放回、不跨层补名额。
- 由用户在上述承诺之后提供一次抽样 seed；用预注册的 SHA256(seed + pack_hash + lane + case_id) 排序取样。单个 seed 和首次样本保留，不换 seed 或挑选重抽。其随机性取决于 seed 未被人为搜索选择，不宣称密码学保证。
- 保存样本清单/hash及每个风险覆盖依据。人工从原件、提案与独立证明审查，不只阅读 AI 总结；每条确认目标、单位/窗口、事实充分性和预期完成/拒答条件。
- 抽样中的数值/口径/来源/授权/状态实质差异为 0 才能通过抽样 Gate；一般排版错误单列，不能把实质差异降为格式问题。
- 出现任何实质差异立即暂停该集合准入，扩查同源/同定义/同拒答规则的全部题；跨类别或边界不清时升级 60 条全量人工审核。扩查发现的错误保留，修订走新版本，不能删除坏题或重抽替换。

该抽样是风险导向加少量随机抽查，不是 20 条简单随机样本。**不据此宣称“95% 置信度全部 Gold 正确”或推导低缺陷率**；也不能把样本通过率写成 60 条业务任务成功率。

## 5. 必须真实人工确认的内容

- 本协议及抽样/扩查规则、残余风险接受。
- 共用业务口径：Invoice Revenue 与 MRR、流失分母/时点、金额存储、币种、时区、覆盖声明、合同身份/历史完整性、缺数政策。可审阅 14/22 份提案的精确清单并批量确认，按 hash 复用，仍需逐项可追溯。
- 抽中的至少 20 条，以及剩余 10 条例外的实际决定；是否认为文档足以支持所要求事实/时期、是否保留合法拒答及因果限制。
- 修订包的具体差异和来源授权范围。批准 Gold 可用于评测不授予新 Dataset/Corpus 权限，不确认负例中故意缺失的业务字段。

AI 可以完成结构/版本一致性检查、原文定位、独立算法复算和风险归类；业务声明真实性、权限授予、争议裁决及风险接受仍需人。模型不进入人工身份字段，也不能自行批准 Registry 定义、Run 或 Live。

## 6. 剩余 10 条的拟议处置

以用户提供的复核意见为依据，建议对这些变化形成统一 **v2 兼容修订包**，原 v1 不删除、不改写。此处仅提案，不创建 v2 或作废 v1：

| Case | 拟议修订与必须保留的限制 |
|---|---|
| 7 条子集 pin 问题 | 精确子索引仅含原授权原件，既有 MCP 全 manifest 校验不变。可优先复用同 Corpus 的新 index version；若原服务需新 Corpus，则生成明确的 Source/Document/Chunk 身份映射并保留原内容 hash，不谎称所有 ID 都不变。需用原服务真实预检通过；预检拒绝不能算正确检索不足。 |
| bh2-001 | 新版评分明确客户主数据关联与账单粒度证据。单表同数值、Gold 准备期的 SQL 对照或包含 JOIN 字符串均不足；须有与该任务同源/同版本的实际查询或可信关系等价/血缘证明。当前链路若不能产出可验收证明，该项继续 blocked，不能改 Runtime/配方或删去要求来过关。 |
| bh2-048 | 明确 evaluation_phase=preflight、business/index 查询与模型调用不发生，不发布 verified 数字、不自动替换版本。保留原 REPORT_SCOPE_INVALID；需确认版本作为用户下一步动作，不强迫错误码改名。文档事实可保留为非执行义务的参考，但从执行覆盖要求中显式区分；其他错误不得一概算正确阻断。 |
| bh2-055 | 预注册条件性展示：有图必须满足原 Chart 契约并保证单位/来源一致，异单位拆图；无图时若数字、单位、来源用文字/表格完整呈现，可判该展示要求满足。此解释须用户明确接受，不回写旧 Gold。 |

v2 应记录 parent_seal、原始 60 条身份到新 case key 的映射、每一变化的理由/人工决定、输入/Gold/索引/评分版本 hash。50 条未变题须逐字节比对以复用适用证据；绑定新版本或受影响的证据必须重验，不能笼统复制 passed。业务定义保持未知的字段仍未知。

若用户批准以 v2 为未来正式评测入口，只在额外的适用性/替代记录中将 v1 标记 superseded_for_future_live 或 not_applicable_for_this_campaign；保留原 seal、旧问题与全部历史。不能追溯宣称 v1 通过了原审核规则，也不能把旧 preflight 失败改记为已修复。

v2 是兼容修订，**不是全新盲集**。所有 60 条保留，20/20/20 分母不缩减，已经知晓的 Gold/失败及协议修改均需披露。不得用这些事实修改冻结候选、Prompt、模型、P3 配方/Verifier、相似度阈值或授权规则。

## 7. 工作量与剩余风险

| 工作 | 原方案 | 新方案基线 |
|---|---|---|
| 一致项人工逐题复核 | 50 | 至少 20 |
| 例外人工逐项裁决 | 10 | 10；已有复核意见复用，仍需明确决定及修订后证据 |
| 逐题人工复核合计 | 60 | 基线 30，减少 30 条/50%；覆盖不足或发现差异时增加，最坏回到 60 |
| 共用 Semantic/Metric 确认 | 必须，且可能重复引用 | 仍必须；14/22 份提案可按明确清单批量确认一次，任务按精确 hash 引用 |
| 审批操作次数 | 容易形成 60 次重复签名 | 可以一次批量提交真实审核清单；所需阅读/判断不能用批量签名免除 |
| 工程准备 | Runner/Scorer/兼容输入仍待完成 | 相同，另需审核 sidecar 与抽样记录；不是立刻节省全部总工时 |

以上仅比较 Case 数量，不声称审核工时可准确减少一半。用户现有第二轮材料可以复用，无需重复抄写，但它明确维持 pending，不能自动换算为 10 条正式人工批准。

主要风险与控制：

- 未抽样题可能残留语义错误；全量机械校验、风险覆盖和扩查只能降低风险，不能消除。
- AI/算法可能共享同一错误定义；人工须核对原件和口径，抽样通过不能证明业务声明真实。
- 同源任务高度相关，20 个 Case 不等于 20 个独立来源；按来源/定义组覆盖并披露相关性。
- 已知问题后的修订可能偏向当前实现；只修输入兼容/评分表达，保留难题、候选冻结和差异历史，不按模型结果调优。
- Registry/权限确认容易被混为 Gold 准入；分别记录并执行原服务校验，尤其不能批准负例中的缺失条件。
- 抽样漏检、审核人关联及 seed 选择偏差；记录真实身份/独立性、一次 seed 和首次样本，不作无依据的统计保证。
- 分级审核不能修复缺失的 Runner/Scorer、关系血缘证明或检索隔离；任一工程 Gate 不满足仍 blocked。

## 8. 生效与最终准入

只有在用户明确批准**本草案的具体版本/hash、20+10 抽样基线、失败扩查、例外处理方向与残余风险**后，才能另行登记协议批准事件。原 pending 历史继续保留，未实际审阅的 Case 不记 human_approved。

后续准入必须同时满足：全量 AI/确定性适用检查无未解决项、真实人工抽查/例外/共用口径确认、版本化修订和授权预检通过、原 Runner/Collector/Scorer 及 P3/RAG/P5B 工程 Gate 通过。届时才可给出 eligible_by_protocol / ready_for_live_authorization；正式 Live 仍需新授权。

本轮不改 AGENTS/生效协议/preflight/原审核记录，不建立新封存包，不写 Registry/数据库，不调用付费模型，不执行正式 Holdout，不提交/推送。**等待用户批准，本提案尚未生效。**
