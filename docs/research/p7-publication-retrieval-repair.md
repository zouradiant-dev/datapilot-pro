## 发布与解释

可信宿主可显式采用 `confirm_document_evidence`：记录已审阅的有限合同，启用部分逐字证据发布及 `evidence-reasons-v1` 解释政策。它不自动批准实际用户合同，也不把文档当作数值证明。

- 已取得真实背景、但数字目标没有 P3 时，报告保留核验过的背景引用，并保留 `p3_evidence_required`。整体不能因此成为 completed。
- insufficient 收据可在显式政策下保留已证明部分，原收据不改成 complete；错误、取消、越权和 unknown 边界保持。
- 没有满足目标的文档证据时，说明缺证据、无法确认结论，不凭空补上“已观察到优先级冲突”的理由。
- 有真实引文但不能确定最终结论时，保留引文，并说明其只支持来源中的陈述。

context claim 新增可选 `evidence_explanations`，默认空时不序列化，原报告投影保持。展示解释的代码必须对应真实 `missing_evidence`；缺失事实明细仍保留原来的 `document_fact_unverified:<fact_id>`，展示 DTO 使用合法的通用代码，避免放宽原名称契约。Report 仍通过确定性重建验证消息和引用。

## 双来源检索

新 `SourceGoal` 是宿主审阅的原问题组成部分，绑定已经授权的 Corpus、IndexVersion 和 Document ID。它包含问题，不包含答案、数值 Oracle 或引用正文。每个必需来源对应一个目标；最多两个，不能增加原来源权限。完整问题仍保留，分解与来源必须经过同一有限合同确认。

显式 `source-goals-v1` 查询政策将这两个问题组成部分放入工具 query 枚举，宿主再次校验实际参数。模型可选择查询顺序；两次搜索上限、Worker/Run 预算和共享一次完成纠正不变。重复搜索仍消耗原额度，第三次搜索被拒绝。默认 legacy/original-first 行为不变。

固定 BGE 512 与原索引向量不变。新相关性政策为 `bge-host-source-goal-cosine-v1`：查询过滤门槛保持 0.55，必需来源按其已审阅问题组成部分计算 goal_score，并携带对应问题 SHA；完整原问题 SHA 同时保留。MCP、Worker 和 Report 校验一致的目标绑定，缺任一必需来源时不能 complete。该显式政策目前限 BGE，不自动扩展到 Qwen。

这改变了原自由查询配方：问题分解由可信宿主审阅，模型不能任意改写查询。它是独立的新策略，不能把其结果与原 60 题的自由查询配置混为同一实验，也不能宣称验证了模型自主分解问题的能力。

## 评分、许可与恢复

新增版本化适配器 `p7-host-source-goals-v1`，复用原宿主评分，仅为新政策校验组成部分 SHA、相关性门槛及逐字引用的运行观察字段。原 v2/v3/宿主评分文件保持原字节，旧分数不改。未知或没有报告的失败沿用原失败结果，不能被新适配器补成成功。

新目标或解释政策进入完整合同哈希；旧付费 Permit 不能自动匹配。实际恢复验证表明，更换问题组成部分会拒绝复用原 Run，原调用和 usage 不增加；终态重复读取复用原报告，不调用模型。

实际生产或新正式实验采用前，仍需审阅完整原问题与分解的等价性，绑定新候选、政策和评分版本。已有合同确认不自动覆盖新分解，之前结束的 Live 许可不可沿用。
