## 完成语义

检索 `complete` 表示已取得符合宿主检索要求的授权相关原文；Report 独立核验全部必需事实、P3 数值及未绑定目标。来源充分与业务请求完整是两个判据。事实缺失不自动把真实合格检索改为 insufficient，也不能因检索 complete 就把业务标为 completed。

| 观察 | 合同处理 |
|---|---|
| 实际检索为空 | unavailable；如仍有独立已验证数值，整体报告可以 partial |
| 原文相关且必需来源齐全，全部业务目标满足 | 检索 complete；Report 可 completed |
| 原文满足检索要求，但部分业务事实无证明 | 检索可 complete；Report 按实际覆盖为 partial/unavailable |
| 缺必需来源、相关性不够或范围不可满足 | complete 被拒绝；非空时 insufficient |
| insufficient 收据且显式部分证据政策允许、有真实逐字证明 | 保留可证明部分，Report 不升级为 completed |
| insufficient 收据且未采用部分证据政策 | 保留原保守行为；不得事后把旧报告解释为已发布引用 |
| 权限、版本、工件完整性、取消或 unknown 故障 | 保留原错误与恢复边界，不能改名为普通 insufficient |

新 `completion_admission.check_retrieval_expectation` 直接调用 Runtime 的原提交校验，以独立 Dev 的真实检索工件核对预期检索标签。充分来源的见证与 insufficient 预期冲突会在准入阶段失败；权限/完整性错误直接保留。它不创造文档、不推断任意问题语义、不修改 Gold，也不授予执行权限。

这项见证检查和状态组合测试必须与未来批次的具体合同审阅一同使用。测试数量、来源 pin 或签名正确，不能单独证明一份新 Gold 的完成语义正确。
