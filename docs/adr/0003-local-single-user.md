# ADR-003：首版单用户部署、身份范围与数据隐私

日期：2026-10-21。状态：规划基线；不是生产多租户安全验收。

## 决策

首版面向本地单用户/可信演示环境。FastAPI、Streamlit、MCP、PostgreSQL 默认本机或私有容器网络，不开放匿名公网上传。dataset_id 是资源标识，不是权限凭据；可信服务端根据本地运行配置和选定数据集创建作用域，模型、文件内容和用户可编辑元数据不能扩大范围。

业务数据读取经 MCP；导入、固定迁移、Seed、健康检查、Checkpoint/预算元数据是明确区分的非模型服务通道。按用途拆分凭据，不让 MCP 从父环境获得管理/Seed/模型密钥。stdio 的环境隔离不能被描述成恶意宿主进程的 OS 沙箱。

## 数据生命周期与可观测性

- 原件保存在受控目录，Git 忽略；预览、产物、Trace 和报告都按范围引用，限制访问和保留期限。
- 模型上下文只含任务所需字段/样本；客户姓名、电话、地址、账户资料默认不发送，不把“只发给模型”误认为脱敏。真实店铺数据向外部模型服务发送前需有明确授权与处理方案。
- Trace 计划用 Langfuse，先定义 TraceSink 接口隔离供应商。默认记录 run/task/attempt、工具、脱敏 SQL 摘要或 hash、usage、时延、错误类型、verdict；原始业务行、含敏感值的完整 SQL/Prompt/响应不默认上传。
- 上传文件和检索文档视为数据，不具有 System/工具授权地位。下载 CSV 时的公式注入防护与输入 XLSX 不执行公式是不同问题，导出功能实施时单独验证。
- 删除包含原件、物理表、元数据、派生产物和缓存的影响分析；通过显式确认操作，不以自动清库/删除卷完成测试。

## 延后到生产化的要求

认证/会话、可信 tenant/principal 传播、授权存储、RLS/角色或数据库隔离、队列与配额、公网上传防护、审计/速率限制、密钥轮换和删除策略必须独立设计并真实测试。当前单用户权限 profile 不能直接部署成多用户产品，也不为未来多租户预建大量空壳。

## 验收与后果

Gate D 验证新用户能在文档列明的本地条件完成上传到报告；选定数据集越权、原始值日志泄露、MCP 环境泄露和路径穿越须有负面测试。生产隔离尚未完成是明确边界，不阻断可信本地 Demo。
