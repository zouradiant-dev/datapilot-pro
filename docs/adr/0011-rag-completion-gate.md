# ADR-011：P6A 的控制工具结束与 Stop Gate

日期：2026-10-21；基线 1d9e96e。本轮仅定向修复 P6A，不实施后续阶段，不自动提交。

## 审计与决策

原 Loop 将无 tool_calls 当作 FinalDecision JSON，格式错误直接失败；真实检索两次额度耗尽后仍展示搜索 Schema，第三次请求直接失败。P5A 对工具集合做精确校验，不能仅从 HTTP tools 中删工具。P5B 的调用 Journal 与官方子图 Checkpoint 必须一起复用。

- 真实 RAG 使用版本化 `rag-submit-v1`，增加宿主本地 `submit_rag_result`，参数沿用 Artifact Digest 与 outcome，补充 `insufficient` 区分非空但不足。SQL 与历史 fixture 仍用原契约。旧真实 RAG Run 没有协议版本时安全拒绝恢复；普通 SaaS 身份不变。
- 模型仍自主选择检索、补查、读取与申请结束。宿主验证来源/任务/授权/版本/结果形状，再记录结束收据；外层原 Coordinator/Verifier/Completion Gate 继续决定整体任务完成。控制工具不是 MCP 写工具。
- 无结束工具的自然语言、可纠正的提交参数错误、陈旧搜索请求共用 **一次** 纠正额度；所有新推理仍由 Gateway/父子预算/Journal 管理。安全拒绝、冲突、取消及不确定外部调用不可纠正。
- 检索额度用完后，仅由宿主规则去掉 search_documents，保留 read_context/submit；ContextManager 检查宿主当前阶段的精确工具集合与初始授权。合法缓存响应可以重放，阶段不能授权新的旧阶段请求。
- 同轮多个提交或提交与其他工具混合时，整批不执行，逐个匹配 ToolMessage。成功提交后直接结束，不再调用模型。已提交收据从原 Journal 重建并复核；纯本地纠正通知原子写入同一调用日志，不建立第二套存储。

## 语义完成范围

初稿仅允许确定性原文定位，这会过度限制语义检索。根据用户补充验收，撤销该限制：区分“检索任务相关且满足要求”“无召回/证据不足”和“最终业务结论未验证”。

没有独立 Evaluator LLM。原文定位可按引用词核对；语义检索则由可信宿主绑定原始目标，在原 RAG MCP 内用固定模型计算候选向量与**原始目标**的独立相关性，结合授权、原件/跨度/哈希、数量和可支持的任务要求验证。模型自己的搜索词、score 或自报完成不构成验收。相关性阈值是工程启发式，不是事实真实性或因果证明；不能支持的时间/全量等要求仍须明确不足。

收据只确认检索任务，永不声明业务结论已验证。P3 指标/因果分析与最终业务报告仍由原外层 Gate/后续 P6B 负责。无需每个 RAG 子任务独立证明最终经营结论。

具体实现将针对文档的时间/全量约束与整体业务分析窗口分开，不把“分析最近三个月流失”机械转成背景文档日期筛选；只有任务要求的可支持检索范围参与 RAG 验收。封闭提取规则和相关性阈值仍是有局限的工程策略，不冒充通用语义评审。固定策略随目标契约进入恢复身份；并发会话查询在既有锁内完成目标向量初始化。

## 参考与验证计划

参考仓库缓存的 Mini Python agent.py 的模型工具循环与 537–628 行可选 /goal；其 /goal 使用独立 evaluator，本项目不复制其 Prompt/实现，不采用该模型评判。沿用已有固定提交索引与许可证引用。

验证正常/错误/混合/重复提交、一次纠正、权限收缩、协议配对、未知调用、真实 PG/MCP/跨进程故障与预算。真实 API 只能在明确有界授权后单次 smoke；Fake 不冒充真实模型。原历史失败与测试记录保留。
